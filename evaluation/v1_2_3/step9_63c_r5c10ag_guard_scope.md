# 测试 guard（v3）的适用范围声明

**定性：guard v3 是防误操作护栏，不是安全边界。**（依你在 r5c10ag 的批准语）

## 它做什么

`evaluation/v1_2_3/step9_63c_r5c10af_test_harness/guard/sitecustomize.py` 通过审计钩子（`sys.addaudithook`）拦截测试进程对仓库的写入、重命名、符号链接、硬链接、FIFO、SQLite 等操作，目的是防止**测试代码或命令的疏忽**改动真实仓库。它配合每次回归运行前后的整仓哈希快照，后者是独立的兜底。

## 它不保护什么（已知且接受）

下列情形 guard **不提供任何保护**，不应被当作防线：

1. 通过 `ctypes`、C 扩展、`cffi` 等直接调用系统调用的代码（不触发 Python 审计事件）。
2. 不加载 `sitecustomize` 的进程：`python -S`、`python -I`（隔离模式忽略 `PYTHONPATH`，而 guard 正是靠它注入）、清空环境变量启动的子进程、其他语言的程序、shell 命令（`rm`、`mv`、`cp`、`dd` 等）。
3. 子进程逃逸：被测代码用 `subprocess`/`os.exec*`/`os.spawn*` 启动的非 Python 程序，或用 `-S`/`-I` 启动的 Python。
4. 在审计钩子安装之前执行的代码（解释器启动早期、`.pth` 文件执行）。
5. 篡改审计钩子本身或 `sys.modules` 的代码（同进程内的恶意代码可以取消防护）。
6. 在仓库之外的路径写入后，通过其他手段（挂载、符号链接目标在仓库外再被别的进程搬入）间接影响仓库。
7. 只读类攻击（读取敏感文件）——guard 不限制读取。
8. 并发的外部进程（其他用户、其他会话）对仓库的写入。

## 因此

- 回归运行**仍然**依赖整仓哈希快照（运行前后逐文件比较）作为独立证据；guard 通过与否都不能替代它。
- 按你的决定，**不再对 guard 做进一步的加固工作**；以上清单只是记录。
- 本次（r5c10ag）的所有激活相关写入入口（指针创建、授权签发）的安全性**不依赖** guard：它们依赖交互终端检测 + 人工键入的确认令牌 + `O_EXCL` 独占创建 + 读回校验，且测试只在临时根目录里执行。
