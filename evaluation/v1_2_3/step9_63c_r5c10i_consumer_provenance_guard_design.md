The artifact path is computed by the consumer, never accepted from artifact or registry as authority.
2. Resolve the exact current r11 freeze. Require revision/path/raw SHA equal the fresh authorization; verify all 20 members. Locate the *single* r11 producer member at the frozen path, require a regular non-symlink file and recompute its SHA. Require it equals the freeze member SHA and the artifact's existing `preflight_script_sha256` field. The artifact's field alone proves nothing.
3. Open the exact new r11 registry path fixed by frozen consumer code, as a regular non-symlink file under a shared lock; never enumerate `*.jsonl`. Strictly parse genesis and every record, rejecting duplicate JSON keys, bad UTF-8/JSON, partial final line, invalid event schema, duplicate claim ID, illegal order or conflict. Genesis producer path/SHA and r11 freeze path/SHA must match independently verified bytes.
4. Find **one** real `PREFLIGHT_INVOCATION_CLAIMED` for the ID and **one** later `PREFLIGHT_ARTIFACT_PERSISTED`; reject missing or duplicate claim, missing/duplicate persistence, any failure event for the ID, or unknown state. Continue validating the entire file after that prefix so later corruption/duplication also fails closed.

Reject missing registry, absent real claim, forged artifact, source drift, malformed log, duplicate ID or any mismatch **before** `adapter.run()`. The proposed v2 [registry schema](step9_63c_r5c10i_registry_schema_contract.json) keeps existing consumer artifact keys and adds only two claim-prefix fields for the new guard. The registry gets new event types/fields that the *new* frozen consumer must understand; these are not silently passed to the old consumer.
