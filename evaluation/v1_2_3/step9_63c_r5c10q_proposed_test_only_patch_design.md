# Step 9.63c-r5c10q — proposed B2 test-only patch design (not implemented)

Scope ceiling: the 12 test modules named in the [B2 matrix](step9_63c_r5c10q_b2_file_dependency_matrix.json). They are not r10 frozen members. No production module is approved for editing. The proposal is phased because *collection pass* is not *test pass*.

1. **Collection pilot, direct-import tests first.** In a separately approved small subset, remove top-level adapter imports and defer them until the relevant test/fixture actually executes. Module-level constants derived from `adapter` must move with the fixture or be independently pinned historical constants, not silently read from a real current pointer. Import the unchanged production adapter only at the test boundary, and expect missing formal identity to fail closed unless an explicitly isolated synthetic fixture is in scope. Do not hide a runtime error by claiming the module passed merely because it collected.
2. **Transitive imports separately.** The r7 issuer test, r7 transport tests and historical preflight tests reach the adapter through other imports. Moving those imports into test setup may unblock collection but does not solve runtime identity. The issuer and some preflight/formal modules are r10 frozen members; editing them is outside B2 test-only scope. The r7 transport itself is **not** an r10 member, but changing its code would still be an infrastructure expansion requiring separate approval.
3. **Runtime identity proof before a passing claim.** Any offline synthetic identity must reside in a temporary root, be conspicuously non-formal, and remain process-local. Preserve exact r11 revision/path/hash checks for formal consumer calls and an independent missing/invalid-pointer negative control. A synthetic `load_identity_config` return at import time alone is insufficient: adapter globals and later root-based validations could point to different identities. Do not inject a fake formal pointer into `evaluation/v1_2_3/` or keep a mocked adapter in shared `sys.modules` for unrelated tests.
4. **Method coverage.** Static inspection found 183 test definitions across the 12 modules. Later implementation must reconcile these against actual collected method IDs; any uncollected test remains a blocker. Then report passed/failed/errors/skipped separately, keeping lifecycle, namespace, issuer, preflight, transaction and Consumer provenance negatives intact.

This design intentionally does not name a production-code patch. If collection or runtime validation cannot be isolated with test-only changes, stop and request a distinct frozen-adapter/identity-contract scope decision. No r10 fallback, authorization issuance, real preflight, model/Agent/RAG evaluation, or V4 execution is an acceptable test fixture.
